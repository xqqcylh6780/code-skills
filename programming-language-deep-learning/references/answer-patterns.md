# 标准答法示范

按这些主线答，不要逐字复制。

## append 的性能和内存

用户问 `append` 干什么、性能和内存如何。

1. `append` 原地把一个元素引用加入 list 尾部，返回 `None`。
2. 【CPython】list 可理解为动态的对象引用数组。
3. 容量够时只写一个槽位并更新长度，通常 O(1)。
4. 容量不足时扩容并搬移已有引用，该次可能 O(n)。
5. 长期连续 append 摊销 O(1)。
6. 额外 capacity 用少量空槽位换更少 realloc。
7. 高频左端入队/出队时考虑 `deque`。
8. 精确扩容公式是 CPython 版本细节，按源码确认。

```text
size=3 capacity=5
[A][B][C][ ][ ]
append(D)
[A][B][C][D][ ]
```

容量满时：

```text
[A][B][C][D]
     ↓ 申请更大槽位区域，迁移已有引用，写入新引用
[A][B][C][D][E][ ][...]
```

## a = b 有没有复制对象

```text
a ──┐
    ▼
  object
    ▲
b ──┘
```

赋值通常是名字绑定，不会因为 `a = b` 就复制整个对象。再用可变/不可变例子说明后续现象为何不同。

## 为什么 insert(0, x) 是 O(n)

```text
[A][B][C][D]
插入 X 到下标 0
[X][A][B][C][D]
```

为给 X 腾出第 0 槽，已有引用通常整体后移。要移动的槽位数随 n 增长，所以是 O(n)。让用户从「数据要不要搬」推出复杂度。

## list 和 vector 是不是一样

相似：连续槽位、size/capacity、扩容、摊销追加。

差异：CPython list 槽位通常保存 `PyObject*`；`std::vector<T>` 通常在连续缓冲里直接存 `T`。由此推出内存密度、cache locality、扩容时移动的是什么、类型约束为什么不同。
